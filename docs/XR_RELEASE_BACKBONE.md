# TRYAMM AR / VR / Mixed Reality Release Backbone

## Principle
AR, VR and Mixed Reality are client surfaces of the same TRYAMM operating system, not separate products with duplicate auth, wallets, rooms or assets.

## Shared backbone
Holo Identity → Quantum Security → HoloNet / Quantum Lag Buster → Supabase state → LiveKit realtime → HoloForge Global Asset Library → Games/Living Worlds → HoloMusic/Omni Box/Isaiah AI TV/Free TV → Marketplace/Money Engine → Aniyah Cross-Border Payments.

## XR continuity
A signed-in user may move between mobile, desktop, TV, AR glasses, VR headset or MR device while preserving:
- account/session identity;
- My World / We Are the World membership;
- Kingdom / New Yahisrale / Metaverse / Middleverse / Multiverse / Holoverse / Living Worlds state;
- LIVE room and audience context;
- chat, PK and creator interactions;
- purchases, entitlements and wallet history;
- creator/follower relationships;
- accessibility/language preferences;
- reusable GLB/Lottie assets and creator inventory.

## LIVE XR
Verified room → device capability negotiation → video/audio/spatial audio → optional avatar/GLB stage → chat/captions/translation → holographic gifts → PK/showcase/talent/karaoke/mic/Vocal Box → recording/replay → reels/clips → HoloMusic/TV distribution.

## Runtime capability tiers
- Flat: web/mobile/TV video and 2D/Lottie overlays.
- Spatial-lite: WebXR/AR placement, 3D GLB overlays, spatial audio where supported.
- Immersive VR: stereoscopic world/stage, tracked head/controllers, spatial UI.
- Mixed Reality: passthrough-aware stage/world overlays, hand/controller interaction, room anchors where supported.

Clients negotiate the highest safe supported tier and fall back without breaking the session.

## Asset reuse
One registered asset can expose multiple renditions:
GLB source → optimized mobile GLB → VR high-detail GLB → AR occlusion/scale metadata → Lottie/poster fallback → game/world prop → LIVE holographic gift/stage prop.

## Controls
Support touch, keyboard/mouse, gamepad/Bluetooth controller, VR controllers, hand tracking where available, voice commands and accessibility/switch controls. No single input method may be required for essential account/payment/safety actions.

## Performance / Quantum Lag Buster
Prioritize safety/accessibility, LIVE voice/video and multiplayer state above background asset downloads. Select LOD, bitrate and asset rendition from measured latency, jitter, packet loss, device memory/GPU and thermal state. Optimization cannot bypass rights/security/moderation.

## Safety
- guardian/boundary configuration for immersive locomotion;
- comfort modes: snap turn, teleport, seated mode, vignette/reduced motion;
- clear exit / mute / block / report controls reachable in XR;
- recording indicator visible/audible in immersive sessions;
- no hidden camera/mic activation;
- age/content/territory gates apply identically in XR;
- purchases require explicit confirmation and cannot be triggered solely by incidental gaze/gesture.

## Accessibility
Captions anchored without obscuring critical view, text scaling, high contrast, mono/spatial-audio alternatives, seated mode, one-hand controller mappings, remappable controls, reduced-motion fallback, voice/switch navigation, screen-reader companion views where headset OS supports them.

## GREEN gate
XR is GREEN per device class only after real device evidence proves sign-in/session handoff, world entry, movement/input, LIVE join, audio/video, captions, chat/safety controls, asset loading, reconnect, performance/thermal limits and exit/resume. A working desktop WebXR emulator does not make headset support globally GREEN.
